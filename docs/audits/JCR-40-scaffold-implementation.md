# JCR-40 Scaffold Implementation Notes

- Issue: `JCR-40`
- Baseline dependency: `docs/audits/JCR-39-parity-baseline.md`
- Goal: Introduce Astro + content collections with parity-safe route compatibility and static GitHub Pages output.

## What was scaffolded

1. Astro build scaffold at repo root:
   - `astro.config.mjs` (`output: static`, site set to `https://jasontsemf.github.io`)
   - `src/` entrypoints and content collections
   - `package.json` scripts for dev/build/preview and parity verification
2. Legacy route wrappers:
   - `src/pages/index.astro`
   - `src/components/LegacyRoutePage.astro`
   - Root route renders from legacy source; all other root-level legacy routes are copied verbatim during build from the route manifest.
3. Content collections (typed migration seeds):
   - `src/content.config.ts`
   - `src/content/pages/*.md`
   - `src/content/projects/*.md`
4. Dist passthrough for legacy assets and microsites:
   - `scripts/copy-legacy-assets.mjs`
   - Copy map lives in `config/legacy-routes.mjs`
5. Baseline parity checks:
   - `scripts/verify-jcr39-parity.mjs`
   - Validates route existence, root HTML parity, redirect semantics, core nav link tokens, and required static directories.

## Route compatibility strategy

- Root routes in the baseline (`/`, `*.html`) are generated by Astro wrappers from existing legacy HTML sources.
- Standalone microsites and demo routes are copied directly into `dist` preserving their original paths.
- Redirect routes (`/binwatch.html`, `/portfolio.html`) are preserved by rendering unchanged source files with the same meta-refresh behavior.

## Local commands

```bash
npm install
npm run dev
npm run build
npm run verify:parity
```

Combined build + parity check:

```bash
npm run build:verify
```

## Scope boundary for JCR-40

- This scaffold intentionally keeps legacy markup as the rendered source for parity.
- Structural component extraction, schema expansion, and SEO modernization remain follow-up work in blocked issues (`JCR-41`, `JCR-42`, `JCR-50`).
